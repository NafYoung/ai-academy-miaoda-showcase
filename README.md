# Athena — 企业学习平台 · 可交互演示

**[在线体验 →](https://nafyoung.github.io/ai-academy-miaoda-showcase/)** 无需登录 · 合成数据 · 可切换员工 / 讲师 / 管理员视角

Athena 是我在实习期间为团队搭建的企业学习平台，原本运行在飞书妙搭上：课程发现、内容投稿、人工审核、学习追踪、AI 辅助题库和课程生命周期治理串在同一套流程里。

这个仓库是它的**可交互演示版**：界面与交互来自真实项目的前端快照，去掉了飞书登录、内部课程和全部真实数据，换成一个运行在浏览器里的演示后端。页面不向任何外部服务发送请求。

## 2 分钟体验路径

左下角的演示条可以切换视角；数据只保存在当前标签页，「重置演示数据」可随时恢复初始状态。

1. **员工学习**：课程中心 →「快速上手多维表格」→ 查看文档 → 课后测验。故意答错一题，系统只让你重做错题；全部答对后进度自动记为 100%。
2. **投稿到上线**：员工「投稿课程」填写并提交 → 切到**管理员** → 后台审核「通过」→「预览并同步」核对写入字段 → 课程管理里「上线课程」→ 切回员工，这门课以「部门必修」出现在课程中心。
3. **AI 候选题 → 人工发布**：管理员 → 课程管理 →「一表人才｜飞书多维表格实战课」→ 测试题 →「生成题目」，选择「快速上手多维表格」作为资料 → 审核和编辑 → 保存并发布。
4. **删除前看清影响**：管理员 → 已下架课程 → 永久删除，先看影响预览，再输入完整课程名确认。

## 我负责什么

- 将学习者、投稿者、审核者、管理员的需求拆成状态明确的业务流程
- 使用 AI 编程工具辅助前端、后端与测试实现，并对生成代码进行检查和调试
- 设计“投稿 → 人工审核 → 同步预览 → 未上线草稿”的受控内容链路
- 设计 AI 辅助题库：AI 只生成候选题，人负责核对、修改与最终发布
- 设计课程下架、恢复、归档与永久删除预览，避免不可逆误操作
- 区分产品已验证事实、示例展示数据与不能对外宣称的结果

## 核心业务闭环

| 阶段 | 用户要完成的事 | 系统控制点 |
| --- | --- | --- |
| 课程发现 | 查找课程，区分必修与选修 | 来源、部门适用范围与个人任务分开处理 |
| 内容投稿 | 保存草稿，补齐部门、资料与课后题 | 不完整内容可暂存，提交前校验关键字段 |
| 人工审核 | 通过或退回课程与题目 | AI 候选不可直接进入正式题库 |
| 受控同步 | 将审核结果写入课程库 | 同步前预览；课程只创建为“未上线”草稿 |
| 学习追踪 | 查看进度、题目和最近学习动作 | 必修、选修和有效学习时长使用明确口径 |
| 生命周期治理 | 下架、恢复、归档或删除 | 永久删除前重新计算影响并要求精确确认 |

## AI 的使用边界

- AI 用于辅助开发、生成候选题与提高内容准备效率
- 人工负责需求判断、原文核对、审核、同步确认与发布
- 正式课程目录同步是确定性流程，不调用 AI
- AI 候选题不会自动保存、提交或发布
- 删除、权限与身份等高风险动作由确定性规则控制

## 演示版与真实系统的区别

| 能力 | 真实系统 | 演示版 |
| --- | --- | --- |
| 登录与身份 | 飞书免登，按组织身份判断权限 | 无登录，三个虚构账号切换视角 |
| 课程数据 | 从多维表格同步正式课程 | 飞书官方公开课程（仅标题、简介与官方链接）+ 标注「示例」的虚构内部课程 |
| 文档与视频 | 授权后内嵌飞书文档、妙记 | 跳转卡片，在新标签页打开公开原文，不加载第三方页面 |
| AI 出题 | 读取所选资料由模型生成候选题 | 不调用模型；为一份公开资料预置了候选题，审核与发布流程完全保留 |
| 组织与人员 | 读取通讯录与部门树 | 虚构公司、部门与人员 |
| 数据存储 | 服务端数据库 | 浏览器标签页内存储，刷新不丢、关闭即清空 |

权限规则与原系统一致：课程上传人可以修改课程内容、管理并发布题库；上下架与删除只归管理员；讲师字段只用于展示，不单独授予权限。

## 技术实现：把平台应用变成静态演示

- **前端原样复用**：`client/` 与 `shared/` 是 Athena 前端的代码快照，只做了脱敏替换（组织名、身份状态值、一个未使用组件里的接入令牌），业务页面逻辑未改动。
- **平台能力替身**：原前端依赖 14 个需要连接妙搭/飞书的运行时模块（登录、请求、用户资料、存储、通讯录、AI 助手等）。构建时通过 Vite 路径别名替换为 `demo/shims/` 下的实现，样式与纯界面组件仍使用原工具包。
- **两个组件改为跳转卡片**：`demo/overrides/` 替换内嵌第三方页面的组件，避免演示站加载外部脚本与统计；点击打开仍计入学习记录。
- **浏览器内演示后端**：`demo/backend/` 实现前端用到的全部接口（57 个请求函数），包括报名、学习计时、答题判分、投稿审核、同步预览、题库草稿与发布、删除影响预览和学习监控。
- **入口**：`demo/main.tsx` 复刻原入口，额外挂载左下角演示条。

```text
client/        Athena 前端快照（页面、组件、接口调用）
shared/        前后端共享的数据契约与业务规则
demo/
  shims/       平台运行时模块的演示替身
  overrides/   两个内嵌第三方内容的组件的演示版本
  backend/     浏览器内演示后端：路由、状态、种子数据、虚构组织
  main.tsx     演示入口与演示条
scripts/       发布前脱敏扫描
```

## 数据与隐私

- 「官方」「合作方」课程的标题与链接来自飞书公开课程页面（飞行社、帮助中心），演示站只做链接，不转存视频、封面或正文。
- 内部课程、投稿、人员、部门与学习记录均为虚构，课程标题带「示例」字样。
- 课程封面由代码生成，未使用任何真实课程素材。
- `npm run privacy:check` 扫描源码与构建产物中的私有链接、应用/表格/字段/记录 ID、飞书私有 ID、接入令牌与凭证赋值；组织名等敏感词通过 `SHOWCASE_PRIVATE_TERMS` 在本机或 CI 传入，不写进仓库。发布流程中该检查不通过即中止部署。

```bash
npm run build
npm run privacy:check
```
