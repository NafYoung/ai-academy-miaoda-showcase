# 验证与公开边界

更新时间：2026-09-02

## 截图如何生成

公开截图不是公司线上页面的直接导出，也没有在原图上做可逆模糊处理。

1. 使用原私有实现的前端界面结构，在本机建立一次性脱敏镜像。
2. 将登录用户、员工、部门、课程、讲师、数量、时间、链接和标识替换为合成示例。
3. 使用本机静态 API fixture 渲染页面，不连接组织身份、课程数据源或后台接口。
4. 截图只保留应用画布，不包含地址栏、租户域名或浏览器标签。
5. 对截图执行 OCR，对仓库执行文本和路径扫描，再允许进入公开提交。

原私有仓库、线上应用和内部数据均未复制到本仓库。

## 已核验事实

- 原私有实现工作区在核验时保持干净。
- 2026-09-02 独立执行 Jest 全量测试：19 个测试套件、162 项单测通过。
- 管理员课程管理接口具有登录门禁与管理员角色门禁。
- 永久删除只允许已下架课程进入，并要求：
  - 重新计算关联影响；
  - 完整课程名确认；
  - 明确确认清理学习历史；
  - 使用与当前影响范围绑定的预览令牌。
- AI 辅助题库输出为候选内容，页面明确要求逐题核对；候选题不会自动保存、提交或发布。
- 课程投稿审核通过后仍需同步预览，目标课程状态为“未上线”。

## 明确不公开

- 公司名称、真实员工、部门、角色名单或组织结构；
- 内部课程、题目、资料、妙记、知识库、学习记录或统计；
- 租户域名、线上应用地址、应用 ID、数据表 / 字段 ID；
- 环境文件、访问凭据、能力配置、部署脚本或数据库结构；
- 原私有仓库的代码、Git 历史、Issue、PR 或发布记录。

## 验证命令

```bash
npm test
npm run privacy:check
npm run screenshots:manifest
```

`privacy:check` 检查受限文件路径、租户资源链接、应用 / 数据表标识和常见凭据形态。截图 OCR 在发布前于本机执行；二进制图片不会被简单文本扫描误判为已检查。
